# 南通长牌

三人双将的单人休闲版：一位玩家、两位电脑。纯 HTML/CSS/JavaScript，无构建步骤；直接打开 `index.html` 或从大厅进入。已登记为「棋牌 / 推荐」。

## 操作

- 点选手牌，再点「出牌」。键盘可用 Tab / Enter 选牌并确认操作。
- 摸牌自动进行；有碰、杠、胡机会时停下来等待，不设操作倒计时。
- 「提示」给出一个按成牌距离和剩余有效牌选择的建议。选牌后显示可能的听牌；不承诺下一张牌。
- 起手或多种杠可选时，直接选择手牌后操作，或通过选牌弹层选择。
- 可查看牌河、规则、各家结算明细；支持音效开关、重新开局、连续对局。
- 本地存储保存本局和累计积分。存储被禁用时仍可正常玩当前对局。打开弹层或切到后台会暂停电脑。

## 本版规则

以 120 张牌、三人双将、可碰杠而不可吃为基础。27 种万条饼与红花、千字、白花各四张；九条属于老将组。牌堆中的两张将牌不参加手牌，也不是万能牌。

胜利结构为七组加一个对子；杠计一组。发牌时可亮起手：四张补一张，三张与一张将凑齐则不补，两张与两张将凑齐则补两张。最后一种仅为额外计分项，不占七组名额。补牌新形成的组合不追认为起手。保留未亮的牌按普通在手牌计分。

胡优先于碰杠；同时可胡时，从出牌者下一家开始依次询问，只有一位赢家。补杠可抢胡，抢胡时原碰保持三张。荒牌时不结算。下一局轮换庄家。

这是写明边界的休闲规则，不代表南通各地统一玩法：不带五张喜牌，不设买庄、报听锁牌翻倍及最低起胡门槛；未实现吕四八胡头等其他规则。所有动作与计分由同一规则引擎处理。

### 计分实现

`engine.js` 的 `baseValue`、`baseScore` 和 `winningScore` 是本版完整计分定义。规则资料中的「翻将对应在手刻子」有 16/24 胡两种说法，本版采用下列明确的 24 胡算法，不混用。

基础值：碰 2、在手刻子 4、明杠/补杠 8、暗杠/在手四张 12、已亮起手 16。老将乘二。每翻到一张同组将再乘二；普通牌按相同点数分组，四老将为一个组。牌面与某张将完全相同时，碰额外乘二、在手刻子额外乘三，起手不额外乘。

三种花牌都构成计分组时，额外加上这三组各自的胡数。手内刻子/四张可以与顺子组成方式并存，但每个牌面只计算一次基础组分。

赢家从所有合法分解中选择本版规则下胡数最高的一种。清胡加 100，飘胡加 50，塌子胡加 20；文钱按一至四组分别加 20/50/100/200。自摸、杠开各加 10；单吊、丫子、边张在当前分解中至多选一项加 10。飘胡、闷飘、天胡/地胡、最后一张自摸各自乘二，再向上进整至十。闷飘允许自家暗杠和起手，不允许碰、明杠、补杠。

其他两家只计算牌面基础分并进整。每位玩家积分变化为 `自身胡数 × 2 − 另两家胡数之和`，所以三家总增减为零。结算中逐项显示计算结果。

## 素材与参考

`art.js` 和 `cover.svg` 是本项目新绘制的矢量素材：30 种简化长牌、牌背、两位人物头像和纸桌封面。牌名辅助识别，图案为原创简化解释，不是传统木版牌逐像素复刻。没有复制商业游戏截图；没有外部素材或字体请求。短音效由 Web Audio 合成。

## 开发与验证

浏览器普通脚本顺序：站点 i18n → 八语翻译 → 引擎 → 矢量绘图 → 交互。引擎同时支持 Node，测试不依赖 npm 包：

```sh
node --test games/nantong-changpai/engine.test.js
```

测试覆盖发牌与牌数守恒、七组胡牌分解、清胡/飘胡/塌子胡、计分牌例、双将两张起手、胡优先于碰、抢杠、非法动作、电脑信息隔离及 200 个固定种子的完整对局。

电脑接收 `view()` 给出的自身手牌与公开信息，不接收其他手牌或未来牌堆。策略用分花色缓存计算七组手牌的成牌距离，再比较可见牌数量估计有效进张；不预测随机牌序。

页面继承全站八国语言。牌面上的中文是图案的一部分，外层数字/花色短名和无障碍标签随语言切换。

### 本次验收

- 10 项引擎测试全部通过，其中包含 200 局固定种子对战（197 局胡牌、3 局流局），逐步校验 120 张牌守恒和有效手牌数量。
- 浏览器实际完成一局人机对战并核对结算，验证保存后继续、下一局轮庄、从推荐区进入和返回大厅。
- 对 320×568、360×640、390×844、568×320、844×390、768×1024、1024×768、1280×720 做视口布局检查，无整页水平或垂直溢出。桌面进行了截图目视检查；小屏主要依据真实 DOM 尺寸与操作区域检查。
- 八国语言共 816 条文案无缺失，320×568 下各语言主要操作均在视口内。大厅字体子集已补齐原字体支持的新增字符并更新缓存版本。
- 直接 `file://` 导航被内置浏览器的协议安全策略拒绝，未进行双击打开的实际浏览器测试；已经检查普通脚本、相对资源路径和无本地 fetch 的运行方式。实际游玩测试在本地静态 HTTP 预览完成。
