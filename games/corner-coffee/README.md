# 街角咖啡店

原生 HTML / CSS / JavaScript 的单人咖啡经营游戏，入口为 `index.html`。已登记在大厅 `games.html` 的「休闲」分类，可搜索「街角咖啡店」。无构建步骤、外部资源或运行依赖，支持相对路径和网站子目录。

## 一轮营业

1. 打开店门，点客人接单。首日 6 位，每天增加 2 位，最多 12 位；最多同时排队 3 人。
2. 取杯，按配方添加材料。每种材料只加一份，顺序可灵活调整，盖盖后不能继续加料。
3. 点「开始萃取」，指针进入绿色区间再点「停止萃取」。初始合格区间为 44–72%，萃取过淡或过苦需要重做。
4. 盖盖，向选中的客人交付。正确配方获得售价，较快完成额外获得 ¥1–2 小费。错单退回并扣 10 秒耐心，超时客人离开。
5. 全部客人接待完或离开后自动打烊，结算营业额、小费、原料与配送费、净利润、退回和废弃数。可从暂停菜单提前打烊。
6. 购买设备，开始下一天。资金、天数、设备及营业中途的订单、杯子、库存、账目均自动保存。

| 饮品 | 配方（每杯包含杯子和杯盖） | 售价 | 基础原料成本 |
| --- | --- | --- | --- |
| 热美式 | 合格浓缩＋热水 | ¥12 | ¥2.6 |
| 冰拿铁 | 冰＋合格浓缩＋牛奶 | ¥16 | ¥4 |
| 冰焦糖拿铁 | 冰＋合格浓缩＋牛奶＋焦糖 | ¥20 | ¥4.8 |

每日每种原料备货量为当天客人数＋4。原料按使用量记成本，倒掉的原料不退款。某种原料少于 4 份时可补货：每种增加 4 份，额外收 ¥6 配送费，新增原料仍在实际使用时计成本。成本在打烊时扣除，即使资金为负也能继续营业恢复资金，不会因重做耗尽原料而卡死。

| 设备 | 价格 | 效果 |
| --- | --- | --- |
| 稳压萃取机 | ¥50 | 合格绿区扩大为 34–82% |
| 节鲜冷藏柜 | ¥80 | 每份牛奶成本从 ¥1.2 降为 ¥0.8 |
| 窗边等候椅 | ¥100 | 每位客人的耐心增加 25 秒 |

## 操作与保存

- 鼠标、触屏点击客人、材料与操作按钮；无拖拽或仅悬停才能使用的功能。
- `1` 拿杯、`2` 加冰、`3` 开始/停止萃取、`4` 热水、`5` 牛奶、`6` 焦糖、`7` 盖盖；`X` 倒掉，`P` / `Esc` 暂停；Tab 与 Enter 可访问所有按钮。
- 打开说明、切换标签页、失去窗口焦点或离开页面时暂停；返回或刷新后手动继续，离线不扣耐心。
- 存档键：`boopland-corner-coffee-v1`，独立于其他游戏。存档损坏时回到初始状态；存储不可用时显示提示，仍可游玩。
- 「重新开店」有确认步骤，仅重置本游戏进度。返回大厅保留公共语言参数。
- 通过项目 `i18n.js` 注册八国语言，没有新增语言开关。沿用项目纸张与铅笔线稿视觉，以及统一的 `analytics.js`。

## 实现与调参

- `engine.js`：不依赖 DOM 的营业状态机、配方、萃取、队列、账目、升级与存档校验。
- `CONFIG` 集中管理初始资金、客人数、耐心、到店间隔、萃取时长、错单惩罚和配送数值；`ITEMS` 为材料成本，`RECIPES` 为配方/售价，`UPGRADES` 为升级价格。金额以 0.1 为整数单位存储，避免浮点账目误差。
- `game.js`：输入、页面反馈、自动保存和暂停。
- `art.js` / `cover.svg`：本地 SVG 咖啡机、杯子、原料、客人与封面；没有嵌入此前的三单演示页面。
- `translations.js` / `style.css`：八国语言与横竖屏布局。超小窗口或放大文字允许必要滚动；帮助和结算使用可内部滚动的弹层。

## 验证（2026-11-09）

从项目根目录执行：

```sh
node --test games/corner-coffee/engine.test.cjs games/corner-coffee/integration.test.cjs
node --check games/corner-coffee/game.js
node --check games/corner-coffee/art.js
```

14 项测试全部通过：三种饮品售价/成本/小费、动作门槛、重复材料、封杯、错单和重复交错限制、废料成本、萃取品质和自动停止、暂停和存档恢复、队列/超时、临界超时结算、补货与负资金、完整一日与三项升级、提前结算、损坏存档、八国语言与占位符、入口资源和大厅登记。原有煎饼游戏的 17 项测试也通过。

浏览器通过本机静态 HTTP 服务实测：大厅搜索→进入→完成首日全部 6 单→结算→购买稳压萃取机→开始第 2 天；同时实测错单退回与重做、键盘 1–7/X、帮助与暂停、刷新恢复、提前打烊、重新开店和返回大厅，未发现浏览器脚本错误。首日测试包含两杯废弃，结果为营业额 ¥100＋小费 ¥10−原料 ¥28.8＝净利润 ¥81.2，与资金变化一致。

布局检查覆盖 320×568、360×640、390×844、568×320、844×390、768×1024、1024×768、1280×720、1920×1080，主要操作均在视口内；八国语言检查了 320×568 与 568×320。针对法/德/西/葡长文案修正了最小竖屏的溢出，并额外检查三人排队、最长焦糖拿铁配方、杯子状态与萃取区之间无重叠。大厅字体子集已补齐新增文案中原字体支持的字符，并同步两处缓存版本。

验收限制：浏览器工具禁止 `file://` 导航，因此直接双击方式仅通过普通脚本、相对资源路径、无模块/网络依赖的静态检查；没有使用实体手机测试触屏。触屏使用标准按钮事件，浏览器尺寸检查不等同于实体设备验收。
