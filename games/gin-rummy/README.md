# 金拉米 · Gin Rummy

纸张、铅笔线稿与低饱和配色的双人金拉米。玩家与电脑对战，先到 100 分获胜。入口为 `index.html`，已登记在大厅的「棋牌」分类。

## 运行与操作

- 使用原生 HTML/CSS/JavaScript，无安装、构建或后台依赖；资源全部采用相对路径。可从大厅进入，也可用普通静态服务器打开本目录入口；代码兼容本地文件方式。
- 首张明牌由非发牌方先选择拿取或让过；双方都让过时，非发牌方必须摸暗牌。
- 每回合先点击牌堆或弃牌堆摸一张，再选手牌，点击「弃掉选中牌」。刚拿起的明牌不能立即弃回。
- 「理牌」循环切换牌组、花色、点数排序；「提示」建议摸牌或选出建议弃牌，不替玩家出牌。
- 系统自动计算不重叠的最佳牌组，并通过下划线和数字标记。选中弃牌后，散牌显示为弃牌后的点数。
- 弃后散牌不超过 10 分可敲牌，0 分可 Gin；也可以继续弃牌，不主动结束本局。
- 支持鼠标、触摸和键盘。Tab 切换控件，手牌区域左右箭头/Home/End 移动焦点，Enter 选择；弹窗可用 Escape 关闭。
- 帮助、新对局确认和结算弹窗会暂停电脑；页面不可见时取消电脑计时，返回后恢复。新对局有确认；取消不影响进度。
- 本场成绩保留在内存中，刷新或离开游戏后重新开始。支持全站八种语言，只有欢迎页提供语言选择；切换语言保留当前手牌、选牌、分数和回合。

## 本作规则

采用 [Gettysburg College / Todd W. Neller 的 Gin Rummy 规则](https://www.cs.gettysburg.edu/~tneller/games/ginrummy/eaai/gin-rummy-rules.pdf) 所述的北美 25/25 计分方式：

- 52 张标准扑克牌，无大小王，每人 10 张。
- 同点数 3～4 张，或同花色连续 3 张及以上构成牌组。A 只作低位，不支持 Q-K-A。
- 散牌 A 计 1，J/Q/K 计 10，其余按面值。
- 普通敲牌后，防守方自动选择最优组合及连续贴牌，减少剩余散牌。敲牌方更少时得差值；防守方更少或相等时反敲，得差值加 25。
- Gin 不允许防守方贴牌，敲牌方得对手散牌加 25。
- 任一方达到 100 分即结束，无额外盘分、局胜奖励或 Big Gin 变体。
- 牌堆剩 2 张时，当前玩家仍可完成弃牌并敲牌；若未敲牌则流局，不计分且不换发牌方。正常计分后双方轮流发牌。
- 自动理牌使用最小散牌组合；同分组合采用确定性选择，不提供手动指定敲牌牌组。
- 电脑决策只读取自己的手牌、弃牌堆和对手公开拿取的牌，不读取对手私有手牌或暗牌顺序。

## 文件

- `engine.js`：与界面分离的牌局、穷举成组、贴牌、计分和电脑策略，可直接通过 Node 加载测试。
- `game.js`、`index.html`、`style.css`：响应式界面、输入、弹窗和暂停调度。
- `translations.js`：中文、英文、日文、韩文、法文、德文、西班牙文、巴西葡萄牙文。
- `cover.svg`、`paper.svg`：独立手绘封面与纸纹资源，无外部素材请求。
- `engine.test.cjs`、`integration.test.cjs`：规则、完整对局模拟、翻译和大厅接入校验。

## 验证记录（2026-11-09）

在工程根目录执行：

```sh
node --test games/gin-rummy/engine.test.cjs games/gin-rummy/integration.test.cjs
```

17 项测试通过，包含 100 场有固定随机种子的完整电脑模拟对局，以及首张明牌双让、非法操作原子性、顺子/同点数组重叠、四张同点数拆分、长顺子拆分、连续贴牌、同分反敲、Gin 禁止贴牌、牌堆耗尽、100 分胜负、电脑不读取隐藏信息、八种翻译键和占位符、大厅唯一路径与本地资源完整性。

浏览器实测：

- 从摸牌、提示、弃牌到敲牌结算及下一局；正常敲牌实测为 8 对 11 散牌，玩家得 3 分，下一局保留分数。
- 明牌禁止立即弃回、取消重开保留手牌、帮助暂停电脑、全站八种语言切换时保留牌局。
- 大厅搜索、进入、返回及语言参数传递；运行期间未发现控制台错误。
- 11 张手牌下检查 `320×568`、`360×640`、`390×844`、`568×320`、`844×390`、`768×1024`、`1024×768`、`1280×720`、`1920×1080`，主要操作无视口外溢。
- 八种语言另检查小竖屏、短横屏和平板，修复日德文小竖屏标题折行导致的纵向溢出。说明与结算使用可滚动弹窗。
- 大厅字体子集补齐新增文案中原字体支持的字符，预加载与字体 URL 的版本号同步更新。

验证限制：内置浏览器安全策略禁止 `file://`，因此未实测双击 HTML 的运行方式；已验证 HTTP 静态服务和相对资源路径。未进行实体手机触屏、不同浏览器内核或屏幕阅读器实机测试。无任何联网对局或云端保存。
